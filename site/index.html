Put a chaperone on your AI agent.

Your agent holds your API keys, your files and sometimes your credit card. Chaperone sits between it and the internet: it caps spend, strips leaked keys, holds dangerous actions until you say yes, and records everything.

How it works

No account. No telemetry. Runs on your machine.

Why this exists

      
Agents act. Mistakes and attacks now cost real money and real data.

      
The settings that protect you usually live inside the same agent that a bad prompt or a poisoned add-on can talk into ignoring them.

    

    

      

        
Runaway bills

        
A stuck loop retries the same call all night, on your key.

        
ChaperoneDaily and monthly caps, a loop breaker and a rate limit. It refuses the next request.

Agents paste file contents, .env lines and tokens into context that is sent to a third party.

How it works

      
One URL change. No code, no plugin.

      
Any agent or SDK that lets you set an API base URL can run through it. Your provider key stays in your agent; Chaperone passes it along and never stores it.

    

    

      

        STEP 1
        
Start the guard

        
Set a budget, keep the defaults for everything else.

        
npx chaperone-ai start --daily 5

      

      

        STEP 2
        
Point your agent at it

        
OpenAI-compatible or Anthropic, streaming included.


export OPENAI_BASE_URL=\
  http://127.0.0.1:8787/v1
export ANTHROPIC_BASE_URL=\
  http://127.0.0.1:8787

      

      

        STEP 3
        
Watch, approve, or pull the plug

        
A local dashboard shows every call and every question. The kill switch stops all requests at once.

        
chaperone kill
chaperone resume

      

    

  






  

    

      
The design choice that matters

      
The guard lives outside the agent.

      
Approval prompts built into an agent are only as trustworthy as the agent. A hijacked agent can be told to change its own settings.

      
Chaperone is a separate process. The agent can't switch it off, edit its rules or see its approval queue. And the text you approve is the raw command, not a summary written by the model.

    

    

      
    

  






  

    
What you get
Nine safeguards, one small process.

    

      
Money
Spend caps
Daily and monthly limits. The next request is refused once you hit them. Local models cost nothing and are not counted.

      
Privacy
Secret stripping
Cloud keys, tokens, private keys and database passwords are replaced with a label before a prompt is sent.

      
Control
Approval for risky actions
Tool calls are rated low to critical. Critical is blocked, high waits for you, and approvals are single use.

      
Safety net
Loop breaker
The same step repeating over and over pauses the agent before it burns the night.

      
Emergency
Kill switch
One click or one command stops every request and cancels everything waiting for approval.

      
Evidence
Flight recorder
Every call, block and decision in a local log. Prompts and secrets are never written to it.

      
Supply chain
Skill scanner
Reads a skill, plugin or MCP server folder and reports what it could do, without running it.

      
Trust
Nothing to trust
No dependencies, no account, no telemetry. Binds to localhost and checks Host and Origin headers.

      
Fit
Works with what you run
Chat Completions and Messages APIs, streaming included. Spend and secret protection also covers the Responses API.

npx chaperone-ai scan ./some-skill

Straight talk

      
A safety net, not a sandbox.

      
Security tools that oversell get people hurt. This is what Chaperone does not do.

    

    

      
It only sees traffic sent through it
An agent with direct internet access, or another API key, can go around it. For hard enforcement, run your agent where the only way out is Chaperone.

      
It judges what the model asks to do, with rules
The rules are heuristics. They catch the common destructive and exfiltration patterns, will sometimes flag harmless commands, and will miss a clever sequence of individually harmless steps.

      
It does not limit what an approved command does
If you allow a command, it runs with your permissions. Chaperone is a checkpoint, not containment.

      
Coverage today
Approval and blocking work for the Chat Completions and Messages APIs, streaming and non-streaming. The Responses API gets spend, loop and secret protection but not tool-call approval yet. MCP traffic is not covered yet.

      
Costs are estimates
Prices come from a built-in table and the usage numbers the provider returns. Caps are checked before each request, so one in-flight request can run past a cap.

      
Tested against mock providers so far
The test suite replays the documented API formats. We are looking for people to try it against the agents they actually run, and to tell us what breaks.
